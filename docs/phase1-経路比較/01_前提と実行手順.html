前提と実行手順

環境の前提 (認証、apply と upload、クォータ) と、取得 → 投入 → 収集 → 再投入の手順

01前提
項目内容
環境dev (us-east-1)。Terraform (infra/envs/dev) を apply 済みで、Lambda 5 関数・Step Functions・S3・DynamoDB・SNS・EventBridge が揃っている状態
認証SSO のプロファイルを AWS_PROFILE で指定する。TF_VAR_account_id (12 桁) と AWS_REGION=us-east-1 も export する。アカウント ID はファイルに書かない
Lambda のコードcd backend && just upload が S3 に置いて update-function-code まで行う。Terraform はコードの差分を見ないので、コードを変えたら upload だけでよい (get-function-configuration の CodeSha256 がローカルの zip と一致することで確認できる)
BedrockClaude Sonnet 4.5 の Marketplace 購読が済んでいること (未購読だと AccessDeniedException)。クォータはリクエスト 50 / 分、トークン 5,000,000 / 分 (Service Quotas の適用値、2026-08-22)
Lambda の同時実行数このアカウントは 10 (aws lambda get-account-settings)。経路 B の Map は並列 5 なので、2 本同時に投入すると TooManyRequestsException が出る (Retry で回復するが、1 本ずつが安全)
ローカルのツールpoppler (pdfinfo pdftotext pdftoppm)。fetch-corpus がページ数と参考文献の推定に使う
課金Textract (LAYOUT + TABLES: $0.015 / ページ) と Bedrock (入力 $3.30 / 出力 $16.50 per 1M トークン) は投入のたびに発生する。Crossref は無料。単価は 2026-08-22 時点の公式料金データ
02手順

1. 論文を集める

cd backend
just fetch-corpus -query 'cat:cs.CL AND ti:"large language model"' -want 5   # testdata/pdf/ に PDF と corpus.json

8〜20 ページの論文を新着から選ぶ。空白を含む -query は引用符で囲む (囲まないと後続のフラグが落ちる)。LaTeX ソースの無い論文は Phase 2 の正解データが作れないので外す。

2. 投入して完走を待つ

export AWS_PROFILE=<profile> TF_VAR_account_id=<12 桁> AWS_REGION=us-east-1
just submit testdata/pdf/<arxivId>.pdf        # jobId (PDF の SHA-256) が表示される
just status <jobId>                           # 実行の状態、TaskFailed の原因、DynamoDB、S3 のキー

実行は 1 本あたり 1 分半〜5 分。Step Functions の実行が SUCCEEDED でも経路が失敗していることがあるので、status の「TaskFailed の原因」と outputs/comparison.json の routes.*.status / missingPages を見る。

3. 成果物を集める (読み取りのみ)

取るものコマンド何に使うか
成果物aws s3 cp s3://<bucket>/outputs/<jobId>/ ./outputs/ --recursivecomparison.json が数値の正 (状態、処理時間、トークン数、差分、verify の報告)
経路 A の中間aws s3 cp s3://<bucket>/work/<jobId>/textract/document.json ...正規化前の構造。raw.json (数 MB) は Textract のブロック座標が要るときだけ
経路 B の中間aws s3 cp s3://<bucket>/work/<jobId>/bedrock/ ./bedrock/ --recursivepage-NNNN.json の usage にページごとのトークン数。欠けたページ番号が分かる
実行履歴aws stepfunctions get-execution-history --execution-arn ... --include-execution-dataState の開始・終了時刻、TaskFailed の error / cause
Lambda のログaws logs filter-log-events --log-group-name /aws/lambda/dev-folio-pipeline-<fn> --start-time ... --end-time ...REPORT 行の Duration。textract-parser は inputTokens / outputTokens をログに出す (bedrock-parser と finalizer はアプリのログを出さない)
DynamoDBaws dynamodb get-item --table-name dev-folio-jobs --key '{"jobId":{"S":"<jobId>"}}'最終状態 (COMPLETED / REVIEW_PENDING / FAILED) と更新時刻

4. 再投入する

just cleanup <jobId>                          # DynamoDB のレコードと uploads/ work/ outputs/ を消す (確認あり)
just submit testdata/pdf/<arxivId>.pdf

jobId は PDF の SHA-256 なので、消さずに再投入すると validator が ALREADY_PROCESSED で止める。再投入は Textract と Bedrock の課金が丸ごと再発生する。
