02経路 A の内訳 (Textract のジョブと Bedrock 整形)

04コスト

算出式: Textract = ページ数 × $0.015、Bedrock = (入力トークン × 3.30 + 出力トークン × 16.50) / 1,000,000。単価は 03。Lambda などの従量課金は含めない。経路 B の欠落ページ分 (失敗した呼び出し) は usage が残らないため含まない。

05設計時の想定との差
  • 設計時は「A はページ単位で安価、B はトークン課金で高い」と想定していた (docs/README.ja.md の 2 つの抽出経路)。実測では A $0.28〜$0.55 / B $0.30〜$0.60 で、5 本とも B の方がわずかに高いがほぼ同額。A は Textract の Tables の課金が 52〜71% を占め、「安価」と言えるほどの差は無い
  • Textract を LAYOUT だけにすると $0.004 / ページになり A は 1/3 以下になるが、表の構造 (セル) が取れなくなる。TABLES の要否は Phase 2 で表の品質を数値で見てから決める (#34 を閉じた理由)
  • 経路 B の入力トークンは tool use 化 (#111) で増えた。同じ論文の 1 回目と 2 回目で 1 ページあたりの入力は 2608.19529v1 が 2,135 → 3,011、2608.19526v1 が 2,190 → 3,066 (tool のスキーマが毎回の入力に含まれるため)。出力も 1 ページあたり 902 → 1,081、686 → 815 と増えているが、1 回目は途中のページまでしか揃っていないので同条件の比較ではない。1 ページあたりの経路 B の費用は 0.0219 → 0.0278 ドル、0.0185 → 0.0236 ドルで、17 ページの論文なら 1 本 $0.1 程度の増加
  • 経路 A の Bedrock 整形は 1 回の呼び出しで済み、出力は 2,826〜9,371 トークン。上限 16,384 に対して最大でも 57% で、#101 で踏んだ上限超過の再発は無かった
06確認できていないこと
  • AWS の請求 (Cost Explorer) との突き合わせはしていない。ここの金額は単価 × 使用量の計算値で、請求は日次集計のため当日中には見えない
  • Textract の非同期ジョブそのものの所要時間は API から取っていない (State の時間から Bedrock 整形の時間を引いた推定)
