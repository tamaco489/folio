01Phase 2 で自動評価する項目

Phase 2 は LaTeX ソースから正解データを作り、30 本で数値評価する計画。今回の目視比較で、自動で測るべき項目と、今の comparison.json / verify では測れていない項目が分かった。

項目 今回の観察 測り方の案
見出しの一致 A は番号を落とし、B は番号と題名を分離する。diff.headings の完全一致は 5 本とも不一致 番号を除いた題名で照合し、階層 (level) は正解の章立てと突き合わせる。番号の有無・分離・段落ラベルの昇格を別々に数える
本文の被覆と重複 A は親節に子節を含む重複 (最大 23,300 文字)、B はページ冒頭の段落や段・ページ全体の欠落 (本文量は A の 53〜71%) 正解の段落ごとに「どちらの経路に存在するか」を判定し、被覆率と重複率を出す。混入 (キャプション、脚注、スタンプ) は正解に無い文字列の割合で測る
表のセル値 大きな数値表で B が数値を改変、A が記号を数値に化かす。小さな表は一致 正解の表とセル単位で一致率を出す (数値セルと記号セルを分ける)。表でないものの誤検出数も数える
図とキャプション B が原本に近く、A は分割・ロゴ・取り違えがある 正解の図の数とキャプションの一致率
参考文献 A は件数一致、B は引用番号の混入と結合。B は固有名詞を書き換える 件数、raw の文字列距離、著者名・arXiv ID の一致率。Crossref は補助にとどめる
字形 A は数学記号と矢印を落とす 正解との文字種別の一致率 (記号クラス)
安定性 B は同じ入力でも JSON の型が崩れることがある (1 / 60 ページ) 同じ論文を複数回流し、完走率と結果の一致率を出す
02正規化 (#22) の確認
  • 番号つき見出しの level を番号から決め直す処理は両経路に効いており、共通の見出しでは level が一致した。ただし番号そのものは A が落としているため、正規化で番号を揃えることはできていない (無いものは足せない)
  • 題名と著者の完全一致は 5 本で成立。要旨は A の行末ハイフン (accu- rately) と en dash の違いで 3 本が不一致。ハイフネーションの結合と ダッシュの正規化を入れれば差分から消せるが、2608.20318v1 の SO that (OCR の誤り) は大文字小文字を無視する比較で既に隠れている。正規化で消してよい差 (表記) と残すべき差 (内容) の線引きが要る
  • 結合セルの扱い (A は複製、B は空文字) は正規化で揃えるべき表記差で、今は揃っていない
