信頼度の分布

provenance.confidence の項目別の値、hallucination 判定、レビュー閾値 (#23) の見直し案

finalizer の verify が各経路の出力に付ける項目別の信頼度 (provenance.confidence) と、レビュー要否の判定 (needsReview)。値の意味は backend/internal/pipeline/verify/ のコードで確認した。

01信頼度の求め方
  • 項目別の confidence は、存在するシグナルの平均: original (原本のテキストレイヤーとの一致)、textract (経路 A のみ。Textract のブロックの確信度)、crossref (references のみ。Crossref で照合できた割合)
  • original は、題名・著者・見出し・キャプション・参考文献の raw は短い文字列の一致 (畳んだ部分文字列の一致なら 1、無ければ隣接トークン対の被覆率)、要旨・本文は被覆率
  • crossref は verified / (verified + mismatch)。notFound は分母に入らず、mismatch は DOI つきで登録題名が違うときだけ起きる
  • hallucination は、短い値の一致スコアが 0.5 未満のもの。1 件でもあれば needsReview: true。項目別の confidence が閾値 0.7 を下回っても needsReview: true

04tables の信頼度は何を測っているか

設計時の想定「tables の信頼度が最も低い」は、経路 A では当たり (title と並んで最低)、経路 B では外れ (ほぼ 1.0)。ただし B の tables の original はセルの文字列が原本のテキストレイヤーに存在するかを見るだけで、05 で確認した数値の改変 (5.84 → 5.34) や列ずれは検出できない (5.34 のような短い数値は原本のどこかに存在しやすい)。B の tables 1.0 は「構造が正しい」ことを意味しない。

05hallucination の判定

5 本 × 2 経路で hallucination は 2608.17950v1 の 3 件だけで、3 件とも偽陽性だった。

経路 path value score 原本
A sections[1].heading 1 Introduction 0 ある (pdftotext -layout で 1 Introduction)
A sections[23].heading 6 Discussion 0 ある
B sections[19].heading 6 Discussion 0 ある

理由: 照合に使う work/text/layer.txt は pdftotext を -layout 無しで作る (二段組で左右の段が混ざるのを避けるため)。この出力では二段組の見出し番号が本文から切り離され、1 と Introduction が別の行に離れて並ぶ。番号 + 1 語の見出しは隣接トークン対が 1 つしかなく、それが原本に無いので 0 になる。3 語の 4 Experimental Setup は対 2 つのうち 1 つが当たって 0.5 になり、閾値 0.5 未満をぎりぎりで免れている。逆に B の 1 (題名が欠けた見出し) は単一トークンが原本にあるので 1.0 で通る。

notFound の大半は arXiv プレプリントや PMLR / JMLR / ICLR など Crossref に DOI を持たない出版形態で、コードの想定どおり。検索そのものの失敗と言えるのは各論文 1〜3 件。

07レビュー閾値 (#23) の見直し案
  • 閾値 0.7 そのものは 5 本 × 2 経路で一度も発動しておらず、今回の REVIEW_PENDING は hallucination (偽陽性) と欠落ページ (#112) だけで決まった。閾値の値を動かす根拠はまだ無い
  • 見出しの照合は番号を除いた語で行う (または番号あり・なしの両方を試す)。今回の 3 件の偽陽性はこれで消える
  • A の title は original が 1.0 なら textract で下げない。2608.20318v1 の 0.75 は原本と完全一致の題名に対する値で、0.7 を切れば要レビューになってしまう
  • Crossref の similarity は両方向の被覆 (または登録題名のトークン数の下限) にし、検索経由の verified を crossref シグナルに重みつきで反映する。今のままでは「verified 12 / notFound 8」のような内訳が信頼度に一切現れない
  • 参考文献の raw に長さの下限 (3 語未満は数えない) を置けば、B の引用番号混入 ([14]) と脚注 URL を検出できる
  • B の tables が 1.0 でも構造は保証されない。表の品質は Phase 2 で正解データと突き合わせて測る
