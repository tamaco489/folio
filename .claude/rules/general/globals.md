# 全般ルール

## 応答

- 日本語・簡潔・直接的に書く
- 絵文字を使わない (明示的に求められた場合を除く)

## 日本語表記

- 括弧は全角 (（）) ではなく半角 `()` を使用し、前後に半角スペースを入れる
- 文中で英字を使う場合は前後に半角スペースを入れる (例: `xxx hoge xxx`)

## コメント

- 「なぜ」が自明でない場合のみ書く。「何をしているか」は書かない
- 句点 (。) を含めない

## Markdown

- ハードタブを使わず、スペースでインデントする
- コードブロックの前後に空行を入れる
- 裸の URL を使わず `[テキスト](URL)` または `<URL>` の形式にする
- 見出しの代わりに太字を使わない
- コードブロックには必ず言語指定をつける
- 同じ内容の見出しを複数使わない

## 図の使い分け

コンポーネント同士を繋ぐ構成図・アーキテクチャ図には draw.io を使う。Mermaid は使わない。

| 図の種類                 | ツール              | 用途例                                             |
| ------------------------ | ------------------- | -------------------------------------------------- |
| アーキテクチャ図・構成図 | draw.io (`.drawio`) | インフラ構成、システム構成、コンポーネント間の接続 |
| シーケンス図・フロー図   | Mermaid (`.mmd`)    | 処理の順序・分岐・フロー                           |

`.mmd` を作成したら PNG に変換する。`--scale 3` を必ず付ける (デフォルトは解像度が低く、日本語テキストの判読が困難になる)。

```sh
npx @mermaid-js/mermaid-cli -i {input}.mmd -o {output}.png --backgroundColor white --scale 3
```
