# 作業の進め方

## 変更を加える前に

- 対象ファイルを必ず Read ツールで読む
- 変更は diff 形式で提示し、承認 (y) を得てから実行する
- `git commit` はユーザーの承認を得てから実行する

## 調査

公式ドキュメントや関連資料の調査は、メインコンテキストを汚さないよう調査用のサブエージェントに委譲する。

即時性は求めない。時間をかけてでも根拠に基づく正確なアウトプットを行う。

## エージェントの報告を検証する

サブエージェントの報告をそのまま受け入れない。以下は自分で確認する。

- ビルド・テスト・lint が通るという主張 — 実際に実行する
- 成果物の性質に関する主張 (アーキテクチャ、ファイル構成、サイズ) — 実際に検査する
- 担当範囲外を変更していないこと — `git status` と `git diff` で確認する

## Git / GitHub

コミットと PR の規約は `.claude/rules/github/` を参照する。

コミットから PR 作成までは `smart-commit` スキルが手順を定義している。
push は Bash の `git push`、PR 作成は GitHub MCP または `gh` を使う (`push_files` は使わない)。

## 並列作業

複数の作業を並行させる場合は `git worktree` で独立した作業ディレクトリに切る。

同じファイルを 2 つ以上の作業が触らないよう、担当範囲を事前に分割する。
`go.mod` と `go.sum` は最大の衝突源になるため、依存の追加を伴う作業を並行させない。
